# P3-003 graph adapter foundation evidence

## Result

- `Assets/AIBT/Editor/Graph/` adds a read-only adapter binding the accepted
  `UnityEditor.Experimental.GraphView` framework (`ADR-P3-014`) to the
  canonical Authoring model:
  - `BehaviorTreeNode : Node` — one visual node per `NodeDocument`, titled
    from `DisplayName`/`TypeId`, an input port always present, an output
    port present only when the resolved `NodeManifest.ChildPolicy.Maximum`
    allows children (absent, i.e. leaf, for `Condition`/`Action` kinds with
    `Maximum == 0`). Styled per `NodeManifest.Kind`, not per node type.
  - `BehaviorTreeGraphView : GraphView` — `Populate(TreeDocument, NodeRegistry)`
    builds one `BehaviorTreeNode` per `NodeDocument` (driven by
    `NodeRegistry.TryGet`, never a per-type `switch`), connects `Edge`s from
    each node's `Children`, and assigns a transient depth/breadth default
    position (`AssignDefaultPositions`) since no `*.aibt.layout.json` reader
    exists yet (that's `P3-005`'s deliverable, per `editor-layout-v1.md`'s
    "missing layout falls back to reconstructed default" rule).
  - `BehaviorTreeGraphWindow : EditorWindow` — hosts the view;
    `OpenFromPath`/`OpenFromBytes` parse via the existing
    `CanonicalTreeJson.Parse` (`AIBT.Authoring`), never `Serialize`, and
    never write to disk.
- `Tests/Editor/Graph/BehaviorTreeGraphAdapterTests.cs` (3 tests, all
  passing): renders a representative fixture covering all four
  `NodeBehaviorKind` values with correct port/edge topology; proves opening
  a document never mutates it on disk (byte-identical before/after) or
  in-memory (`TreeDocument.Revision` unchanged — `Revision` only advances
  through `Mutate()`, which `Populate` never calls); confirms an unresolved
  node type renders without throwing.
- `Tests/Editor/Graph/Fixtures/four-kinds.aibt.json` — new fixture (none of
  the existing golden trees exercised all four kinds together): a
  `aibt.core.memory-sequence` (Composite, built-in) wrapping an
  `aibt.core.inverter` (Decorator, built-in) around a `sample.graph-condition`
  (Condition) leaf, alongside a `sample.graph-action` (Action) leaf. The
  `sample.*` prefix (not `aibt.test.*`) is required: `NodeRegistryBuilder.AddUserExtension`
  explicitly rejects the `aibt.test.` namespace, which is reserved for
  `AddTestFixtures`'s internal reference-handler-bound fixtures.

## Decision

No new decision. Applies the already-accepted `ADR-P3-014` framework and the
`P3-002` layout contract's "framework-native vs. AIBT-owned" statement:
`GraphView` provides no persistence, so this adapter's positions are
explicitly a placeholder, not a `P3-002`-contract implementation.

## Scope and limitations

- **No `.aibt.layout.json` reader exists yet.** Positions are a simple
  depth/breadth default (not the deterministic auto-layout contract from
  `editor-layout-v1.md` — that is `P3-004`'s deliverable). Do not read this
  adapter's placement logic as satisfying any part of the `P3-002`
  determinism contract.
- No live interactive-Editor session was used; all checks ran through
  `Run-UnityTests.ps1 -Mode EditMode -Scope Focused` (batchmode,
  `-nographics`), consistent with `P3-001`/`P3-014`'s own headless
  precedent. Actual pointer-driven interaction was not exercised (not
  required by this card — no editing, read-only rendering only).
- Node visual styling (color per `NodeManifest.Kind`) is a minimal
  placeholder; no design/UX pass was done. Not a card requirement.
- `Editor/Graph.meta`, `Tests/Editor/Graph.meta`, and per-file `.meta`s were
  generated by the Unity Editor itself during the compile/test run below,
  not hand-authored.

See `verification-results.json` for exact commands and pass/fail detail,
including the two intermediate failures fixed before the final green run
(a `NodeRegistry` unqualified-name ambiguity against the sibling
`AIBT.Tests.Editor.NodeRegistry` namespace, and using the reserved
`aibt.test.` prefix with `AddUserExtension` instead of `AddTestFixtures`).
